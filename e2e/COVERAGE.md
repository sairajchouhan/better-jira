# E2E coverage: bun-test CDP harness → Playwright Test

The old suite was 334 `bun test` tests in 48 `e2e/*.e2e.ts` files on a custom CDP harness (`e2e/harness.ts`), run serially: **9 min 43 s** wall.
The new suite is 111 Playwright tests (user-story flows of `test.step`s) in 49 `e2e/*.pw.ts` files on `e2e/app.ts`, 6 workers: **about 1.3 min** wall.

Every old test is listed below with the flow (and step) that now covers it. Step titles keep the old test titles, so defect IDs (R2-…, D…, B…) still grep.
Unless a section says otherwise, nothing was dropped.

## Changes that apply to every file

- **Harness → `e2e/app.ts`.** The same page wrapper (`open`, `click`, `key`, `type`, `eval`, `waitFor`, `cmd` for raw CDP), now over Playwright pages. Each worker runs its own `scripts/fixture-server.ts` on port 3200 + worker index; the fixture is reset before every test, and each `open()` gets a fresh browser context (fresh storage).
- **Timing budgets** (for example, menus open in under 100 ms) are unchanged. They are measured in the page as before.
- **Fixed sleeps** that waited _for_ something became waits on that thing (`waitFor`, `expect.poll`, saved IndexedDB/localStorage state, fake-Jira counters). Sleeps that prove something does _not_ happen within a window were kept. Of about 67 s of `Bun.sleep`, the kept ones are listed per file.
- **Clipboard:** CDP `Browser.grantPermissions` → `context.grantPermissions`. **Downloads:** CDP download behaviour plus polling the folder → Playwright's `download` event (`savedAs`), checking the suggested file name and the saved bytes.
- **`try/finally page.close()`:** removed; the fixture closes every context. Closes that are under test (two-tab takeovers) are kept.

## harness-guard.e2e.ts → fixture-launch.pw.ts

| Old test                                                                                          | New test                                                                                       |
| ------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| a second harness fails on an occupied fixture port instead of testing the old server              | a fixture launch fails on an occupied port instead of testing the old server                   |
| a killed test process leaves no fixture server or browser behind, even before its parent reaps it | a fixture server exits when its runner goes away (stdin closes), even if the runner was killed |

Changed: readiness now comes from the child's own "Disposable browser fixture on" line, so a server already on the port can never be mistaken for ours. The server exits when its stdin closes (`FIXTURE_EXIT_ON_EOF`), which the OS does when the runner dies however it dies. The test closes stdin directly instead of SIGKILLing a Python-wrapped runner. Browsers are Playwright's to clean up and aren't tested.
